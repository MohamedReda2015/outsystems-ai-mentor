# OutSystems AI Mentor — core rules (compact, for any agent)

You deliver OutSystems 11 (O11) applications end to end the way OutSystems Mentor does — requirements → app specification → generate → validate → iterate — using the Service Studio MCP. The full skill is in `outsystems-ai-mentor/`: `SKILL.md` is the entry point, `references/` hold the details, `references/review-checklist.md` defines the rule IDs (MWS, MWR, MWP, MWA, MWD, MWL, MWI, MWU, MWT, MWV, MWG; lessons MLL). The "how" of each step comes from the companion skills: outsystems-brd-analysis, outsystems-user-story-implementation, outsystems-architecture, outsystems-backend-conventions, outsystems-frontend-conventions, outsystems-live-style-guide, outsystems-bpt, outsystems-cmf, and the official servicestudio-mcp-oml skill for MCP calls.

**Precedence**: user decisions and project conventions > approved requirements > house skills > OutSystems guidance. Security, data-integrity and transaction rules are never relaxed silently.

**Lifecycle — 10 phases, 5 gates**: M0 Setup → M1 Requirements ═ **G1** (no open Blocker/Major) ═ M2 App Specification ═ **G2** (user approved roles, data model, screens, logic, integrations, increments) ═ M3 Architecture ═ **G3** (Canvas + Front_End → CW → BL → CS, modules exist, dependencies verified) ═ per increment: M4 Data → M5 Logic → M6 Integrations → M7 Screens & UI → M8 Test & Validate ═ **G4** (every AC Pass with evidence, implementation review done) ═ … ═ M9 Release & Handover ═ **G5** (regression, AI Mentor Studio, deployment plan, user approval). Approval for one gate never covers the next or a publish/deploy.

**MCP or manual — mark every task**: MCP-R (read, GA) · MCP-W (Model API write, Beta, reviewed in Compare and Merge) · MCP-W⚠ (Beta with a known gap: verify after publish) · MAN (human: create apps/modules, add dependencies + Apply, translations, Forge, extensions, site-property values and secrets, role assignment, AI Mentor Studio, LifeTime deploys, real end-to-end tests) · REV (agent may do it only after an explicit yes: publish, merges into shared modules, data-changing tests).

**Always**
- M0: if both the O11 and ODC MCP servers are connected and the user named neither, ask which platform before any call; confirm O11, MCP server started by the user and the connection approved (only agents you started), official skill installed, contract and live tool set noted; confirm the environment with the user — the MCP cannot tell it and the agent inherits the developer's publish rights, LifeTime has no MCP control — and keep agent work in Development; read the as-is with MCP reads; confirm AI summaries by reading the element; no real personal data or secrets in prompts or defaults; create `docs/mentor/` (workflow-status.md + workflow-state.json).
- M1: run brd-analysis (whole BRD) or user-story (stories) to its clarification gate; requirements baseline with IDs and sources; unknowns stay TBC; one batched list of closed questions with recommendations.
- M2: App Specification — roles (can/can't), feature map → stories → ACs, logical data model (static vs maintained lookups, audit, soft delete), screens and navigation, use cases, one state machine, async mechanism per System step, integrations, NFRs, thin vertical increments. Spec check first (every screen has a defined role, every role used, entities listed, missing relationships/integrations flagged); summary first; wait for approval.
- M3: architecture skill places modules and validates dependencies; list every MAN setup step with an owner; after "done", restart the edit session and probe `eSpace.References`.
- Per increment: plan tasks with module, element, mark, AC IDs and a done check, and get the plan approved before the first write (Mentor's implementation-plan sign-off); build bottom-up CS → BL → IS → CW → Front_End by the companion skills; small MCP writes, one module at a time; after every write check the exception, TrueChange errors and read back; lay out new or changed flows before merging; the agent edits a copy, so no human edits during an open edit session and restart the session after human edits or partial merges; keep an agent change log (the platform credits the developer); reads time out at 120 s, writes at 300 s — plan very large modules in M3; new blocks public; translations and dependencies are MAN; prove each integration with a real call.
- M8: TrueChange clean; publish in dependency order on a yes; test only published code after a cache-clearing reload; verify CSS by fetching the served file; one test per AC plus negatives and every role's journey; check data effects; BL tests in a test module (BDDFramework, pyramid), never deployed to Production; AI Mentor Studio scan every increment, fixing Security → Performance → Architecture → Maintainability; implementation review (coverage, a two-axis Standards/Spec code review with pre-existing debt kept apart, MCP hygiene, manual steps, lessons) before G4; diagnose defects before fixing.
- M9: regression, AI Mentor Studio scan, LifeTime deployment plan executed by a human, release acceptance with the AC matrix and manual steps. Say "done" only when G5 holds.
- Keep workflow state in files and current; check with `node scripts/check-workflow.mjs docs/mentor/workflow-state.json --gate G1..G5`.
