# Lessons learned (MLL)

From real O11 projects built with agents and the Service Studio MCP in 2026, from OutSystems Mentor release notes and community discussion, and from the companion skills' lessons. Each lesson: what happened → the rule it supports.

- **MLL-01 — Screens before the spec.** An agent asked to "build the app" generated list and edit screens from the first entity it inferred; the business statuses and roles were wrong and most screens were rebuilt. → Spec and data model approved first (`MWP-07`).
- **MLL-02 — "I added the dependency."** Twice a user said a dependency was added before clicking **Apply** in Manage Dependencies; once it was applied but invisible until the edit session was ended and restarted (`omlReset` was not enough). → Probe `eSpace.References` after restarting the session (`MWA-05`).
- **MLL-03 — Workarounds for missing tools.** Attempts to write translations or add references through the Model API failed or produced half-applied state. → Mark MAN and deliver exact steps (`MWG-06`).
- **MLL-04 — Big-bang build.** Building every entity, action and screen before the first publish produced a long tail of dependency, publish-order and validation errors found all at once. → Thin vertical increments with publish and test each (`MWP-08`).
- **MLL-05 — Merged is not deployed.** A block stylesheet edit merged cleanly and showed in the model, but publish shipped the old CSS three times. Only fetching the served CSS file revealed it. → State merged/published, verify served CSS (`MWT-02`).
- **MLL-06 — Stale state.** A resumed session trusted its notes; the user had edited the module meanwhile, and Service Studio had kept the user's edit and dropped the agent's pending change. → Re-read the model before continuing (`MWG-05`, `MWG-07`).
- **MLL-07 — Silent spec drift.** Small "while I'm here" changes during build (extra status, renamed button) broke a sibling story's hand-off. → Change requests update the spec and re-run affected ACs.
- **MLL-08 — AI summaries as facts.** A module overview said an action "validates the user's role"; reading it showed the check was only on the client. → Confirm by reading the element (`MWS-02`, `MWU-02`).
- **MLL-09 — Large modules time out.** Calls on ~10 MB modules ran 2–4 minutes; the default timeout killed the sidecar, and one module could not be written at all. → Raise timeouts, call through a script, or build the piece in a small module and let the user drop it in by hand (`MWG-06`).
- **MLL-10 — Missing Start/End nodes.** Service Actions created through the API had no Start or End node and failed validation. → Write check after every write (`MWG-07`).
- **MLL-11 — New blocks are private.** Front_End could not reference a new CW block until `Public` was set and CW republished. → Include "public + publish producer + add dependency (MAN)" in every cross-module UI task (`MWU-01`).
- **MLL-12 — Integration "works" on paper.** A gateway was tested with one provider while another was configured; messages never arrived. → Prove each integration with a real call on the target environment (`MWI-02`).
- **MLL-13 — Secrets in defaults.** The agent could read a secret site property's default value. → Keep secret defaults empty; values per environment by a human (`MWS-04`, `MWI-03`).
- **MLL-14 — Approval creep.** "Go ahead" for the plan was read as permission to publish and to run an approval on shared data. → Approval per gate and per action (`MWG-04`).
- **MLL-15 — Generated drafts need hardening.** Agent-generated first drafts had screens open to all registered users and business-maintained lists as static entities; community reports describe generated starter apps needing the same hardening. → Security and lookup decisions are explicit in the spec and reviewed at G4 (`MWP-01`, `MWD-03`).
- **MLL-16 — Documents with tables.** Requirements uploaded with status and field tables lost the tables during generation (Mentor at release ignored images and tables). → Convert tables to text before analysis; check the baseline against the original (`MWR-02`).
- **MLL-17 — The agent edits a copy.** A developer fixed a screen in Service Studio while the agent's edit session was open; the agent kept reading its own copy, never saw the fix, and its next merge proposed to overwrite it. Partial merges also reappeared in the next merge. → No human edits during a session; restart the session after human edits or partial merges (`MWG-08`).
- **MLL-18 — Which environment?** With modules from two infrastructures open, nothing in the MCP said which one a module came from, and the agent had the developer's rights to publish beyond Development. (*Community Idea; OutSystems "evaluating options".*) → Confirm the environment with the user; agent work stays in Development by agreement; keep an agent change log, because Service Center shows the developer's name (`MWS-06`, `MWG-09`).
- **MLL-19 — Generators do the skeleton, not the hard parts.** Mentor's App Generator (ODC) produces data, roles, authorization and CRUD screens well, but at launch did not generate Workflows or ad-hoc REST endpoints and Service Actions, and handled complex logic weakly; agent generation on O11 shows the same profile. → Skeleton in increment 1; processes, integrations and complex rules as explicit, risk-first increments (`MWP-08`).
- **MLL-20 — Big modules break reads too.** On very large O11 modules even listing action names exceeded the 120 s read timeout; restarting Service Studio did not help. A community workaround read an exported `.oml` snapshot with Service Studio's own tooling, read-only. → Check MCP feasibility per module in M3 and plan around it (`MWA-07`).
- **MLL-21 — Debt found late is expensive.** Teams that ran AI Mentor Studio only before release faced a long list at the worst moment; practitioners recommend recurrent analysis and fixing security first. → Scan every increment, in priority order (`MWV-07`).
